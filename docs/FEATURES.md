- [L] `capture-virtual-output`: stream a virtual output sized to the client. Add `SourceKind::Virtual` (ashpd 0.13 offers `SourceType::Virtual`; `portal_sources` maps only monitor and window), send the client's swapchain size, refresh rate and colour volume in the handshake, and use them for `video.resolution`/`frame_rate`; later resize live through the encoder reopen path. Removes the host downscale and client upscale and makes a monitorless host work. Start with a per-compositor spike (Mutter, KWin), since sizing virtual streams is compositor specific
- [M] `present-pacing-live`: run `video.present_pacing = "latency"` and `"smooth"` against a live compositor (KWin, Mutter, a wlroots one) at a fixed refresh and with VRR: run the `#[ignore]`d feedback test in `window/surface.rs`, confirm one `presented` per drawn frame with the `vsync` flag, that latency mode lands on its targeted vblank with the default 3 ms margin (or how far the adaptive margin grows on each compositor), and that smooth mode holds a steady capture-to-display figure; tune the defaults and decide whether either mode should become the default. Target times through `wp_commit_timing_v1` stay out of reach while Mesa's WSI owns the surface's commit timer (`client.md`)
- [XL] `video-ltr-recovery`: recover from loss against a client-acknowledged long-term reference instead of an IDR. Every recovery path forces an IDR today (`rusplay-host/src/encode.rs`, `pipeline.rs`), a large burst at 4:2:2/4:4:4 10-bit. The NVENC SDK 13 structs already carry the LTR fields and the VAAPI encoder writes its own headers, so the reference structure is Rusplay's. Split into: client acks of the last good frame and a recover-from-frame request (protocol bump), an encoder-trait method to invalidate or mark references with IDR fallback, then per backend (NVENC LTR, VAAPI AV1 slot refresh first, H.264/HEVC long-term refs after; VCN's own reference marking, see `decode-vaapi-driver-field-long-term`, makes those risky)
