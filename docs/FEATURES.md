# Networking
- [M] `net-adaptive-bitrate`: close the bitrate loop. The host already applies `ControlMessage::BitrateHint` live (`rusplay-host/src/control.rs` → `mailbox.set_bitrate`, every backend's `set_bitrate` keeps it across reopens) but nothing outside tests sends one, and `ReportLoss` only bumps `packets_reported_lost`. Add a client-side controller on the receive stage (fast decrease on `PacketsMissing`/`FrameLost`/keyframe requests, slow increase back towards `video.bitrate_kbps`) that sends hints off the frame path, with enable, floor, step and window options in `network`; clamp hints on the host to a configured range, since today any client-supplied kbps is applied unchecked. It does nothing under `RateControl::ConstantQuality`, so either carry the rate-control mode in `StreamFormat` or have the host ignore hints there
- [S] `net-announce-busy`: add a busy flag to `Announce` so a client's host list can show a host that is mid-session before the user tries to connect; the discovery responder runs on its own thread, so `HostSession` has to expose its busy state to it; a protocol version bump
- [M] `net-session-takeover`: let an authenticated reconnect `Hello` from the current session's own `PeerId` replace the session's client address, so a restarted or roaming client does not wait out `peer_timeout_ms`; it must re-run full authentication and reset the `ControlChannel` and `Reassembler`, never trust a bare source address
- [S] `stream-capture-timestamps`: carry the capture timestamp (µs since stream start) with each video frame, in the first fragment or the stream header, instead of the client stamping receive time (`client.md`: video packets have no timestamp field), estimate the host/client clock offset over the control channel, and report capture → decode → present latency in `ClientStats`; a protocol version bump
- [S] `net-announce-host-id`: carry a stable host id (the id of a host key or a random id kept in the state directory) in `DiscoveryMessage::Announce`, with a protocol version bump, so the app matches a discovered host to its saved pairing across a rename or address change instead of by display name and address (`HostList::merge_discovered`)

# Session
- [L] `session-format-negotiation`: negotiate codec, chroma and depth from what both ends can do. `rusplay_encode::capabilities` exists "so a session can negotiate the stream format with the client" (`video-encode.md`) but only tests call it, and `Hello` carries only the version. With the defaults (VAAPI, HEVC, 4:2:2) a radeonsi host refuses to open, and a client may be sent a format it cannot decode. Add a decoder-side `capabilities`, send it in `Hello` or a new control message, intersect on the host with the configured format as first preference, and announce any change in `StreamFormat` (never silent, per the no-silent-downgrade rule); define the no-overlap case as a specific error. Protocol version bump
- [L] `capture-virtual-output`: stream a virtual output sized to the client. Add `SourceKind::Virtual` (ashpd 0.13 offers `SourceType::Virtual`; `portal_sources` maps only monitor and window), send the client's swapchain size, refresh rate and colour volume in the handshake, and use them for `video.resolution`/`frame_rate`; later resize live through the encoder reopen path. Removes the host downscale and client upscale and makes a monitorless host work. Start with a per-compositor spike (Mutter, KWin), since sizing virtual streams is compositor specific
- [L, blocked by: stream-capture-timestamps] `present-pacing`: pace presentation to the display. The client draws on arrival in mailbox, immediate or fifo with no `wp_presentation` feedback, commit timing or VRR anywhere; with host timestamps it can schedule presents, present at the host cadence on a VRR display and phase-align on a fixed one. Depends on what wgpu and Mesa WSI expose
- [XL] `video-ltr-recovery`: recover from loss against a client-acknowledged long-term reference instead of an IDR. Every recovery path forces an IDR today (`rusplay-host/src/encode.rs`, `pipeline.rs`), a large burst at 4:2:2/4:4:4 10-bit. The NVENC SDK 13 structs already carry the LTR fields and the VAAPI encoder writes its own headers, so the reference structure is Rusplay's. Split into: client acks of the last good frame and a recover-from-frame request (protocol bump), an encoder-trait method to invalidate or mark references with IDR fallback, then per backend (NVENC LTR, VAAPI AV1 slot refresh first, H.264/HEVC long-term refs after; VCN's own reference marking, see `decode-vaapi-driver-field-long-term`, makes those risky)

# Audio
- [M] `audio-microphone`: send a client microphone to the host. Audio is host → client only and `AudioCapture` always sets `STREAM_CAPTURE_SINK`, so it cannot capture a source.
